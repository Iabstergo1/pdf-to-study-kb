# 故障排查

## 启动与解释器

网页连接失败时重新使用终端打印的启动链接。不要把 localhost 与 127.0.0.1 的连接凭据混用。端口 8765 已被占用时先关闭旧服务。

Python 缺少模块时检查是否选中了 study-kb 环境的解释器。在设置页粘贴 python.exe 的完整路径，然后重跑环境检查。不需要重装现有环境。

## 模型与看图

登录失效时重新登录；API key 出错时检查厂商和协议是否对应。模型名单不代表账户有权限调用每一个型号，看图测试会实际验证。

三轮普通字体测试有一轮不匹配，就不能启用此模型入库。请查看任务记录，不要用“声明支持图片”绕过测试。

## 入库失败与锁

查看任务日志和来源的检查报告。lint 失败选择“按报告修复”；网络恢复后选择“继续入库”。恢复包拒绝继续时保留错误信息，通过维护工具或 pipeline-doctor 诊断，不要删除 SQLite 文件。

ChatGPT / OpenAI Responses 在收到响应头之前遇到可识别的临时连接错误，会等待 1 秒、2 秒各重试一次同一模型请求，已执行的工具不会重跑；仍失败则停止。日志的 `[network]` 行记录目标主机、错误码、耗时和次数，不记录令牌或请求正文。重试可能额外消耗额度。HTTP 错误、证书错误和未知原因不会自动重试；额度耗尽仍需手动继续。响应头前重试耗尽后，不再叠加会话续跑重试。

`Request timed out` 表示请求等待超时。单次等待响应头默认最多 10 分钟，到期计入上述两次重试上限；连续三次都超时会等待约 30 分钟后停止。用户点击“停止”会立即取消当前请求或重试等待。超时本身不能证明是模型推理慢还是网络/上游没有及时响应，不需要因此重新登录或重做看图测试。

`OAuth refresh failed ... fetch failed` 表示续期请求的传输失败，不能单凭它认定授权失效。续期和账号模型列表请求也会最多重试两次，每次独立限时 15 秒。收到 HTTP 拒绝后立即报错，保留原凭据，不自动重新登录；OAuth 错误响应正文不会写入日志。取消会停止等待和后续重试；已经发出的续期若返回新令牌，SDK 仍会保存，避免丢失轮换后的凭据。

`terminated`、socket 断连等发生在响应流途中时，`[network] ... stream_code=...` 记录可取得的底层原因，缺失则显示 UNKNOWN。入库在同一会话内退避 1 秒、2 秒最多续跑两次，直到本窗 U7 交接完成前都共用这两个名额；失败回合的残缺消息不会重发，其中工具也不会执行。`[network-recovery]` 表示正在恢复，不需要再次点击。认证失败、额度不足、上下文超限和流水线错误不会进入这条恢复路径；两次仍失败再由用户手动继续。恢复可能额外消耗额度。

每窗完成记账、实际更新阅读摘要并通过恢复检查后，待整批工具结束才自动换一个会话；同批先更新摘要再记账也可以，但原样重写旧摘要不算更新。执行记录中的 `[handoff]` 表示交接成功，仍是同一次入库，不需要再次确认。新会话重读规则、全书地图和摘要，旧图片不会持续随请求重传，必要的证据仍会重读。最后一窗交接后继续综合整理和发布；`DONE` 仅表示窗口已完成。收尾会话获得全来源页面清单和本轮已记账路径，避免只看最后一窗。交接减少历史累积，但不能保证网络或上游不再超时。

文件名写错、编辑文本未匹配等普通工具错误会返回给模型纠正；成功的工具不会自动重跑。连续三轮回答没有完成窗口或阶段进展才停止。不可恢复或已耗尽重试的模型请求失败、无法读图、流水线状态失败和 lint 失败仍会停止，不用无限重试掩盖问题。

资料详情的“查看执行记录”可找回已结束的任务，失败原因也会显示在详情中。“执行失败”表示本次任务已停止；处理窗口数统计已完成的窗口，读规则和初始化摘要不计入窗口进度。

首次启动在创建摘要前中断时，点击“继续入库”。只有确认尚无窗口阅读/处理记录、可写页面与工单快照一致时，才重新进行摘要初始化；已有进度却丢失摘要仍会停止，不自动编造历史记录。

若唯一问题是摘要的 RESUME 落后于已完成窗口，网页会让当前模型先核对账本、重读需要的证据并补齐摘要，再通过原恢复检查继续。在此期间不能推进窗口或写知识页；连续两轮仍无法核对就停止。工单缺失、账本冲突等其他错误仍需诊断，不会跳过检查。

维护操作先预览，再输入目标名称确认。活跃锁不能强行释放；确认其他会话已经停止后，等待超时，再使用 unlock。中止会结束子进程树，包括 MinerU 子进程。
